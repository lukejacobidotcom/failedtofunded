Positioning widgets for TradeSyncer

Three drop-in widgets that show what profitable and unprofitable futures traders are actually doing, right now. One script tag, one HTML element, no build step, no iframe. Every widget degrades gracefully when the market is closed or the feed is unreachable — it never shows a blank box and never claims to be live when it isn't.

1 · Compact positioning card

360 × 150

Built to the exact box you specified. Fixed height — it will not push your dashboard grid around. Instrument switcher is a native <select>, so it behaves correctly on mobile. The (i) opens an explainer inside the card rather than a popover, so nothing ever overflows the 150px.

Live preview state: 
<mkfm-positioning-card symbol="MNQ"></mkfm-positioning-card>

2 · Six-instrument rail

fluid width × 92

A full-width strip for the top of a dashboard. Scrolls horizontally below 640px and stacks the label block above the cards. Each cell carries the instrument's last price and session change on the right of its header, then the two cohort bars beneath it, then the trade count behind the reading. Price comes from a separate feed fetched in parallel; if it fails, the cell renders positioning without it rather than blocking. See What these numbers are for how each figure is computed.

Live preview state: 
<mkfm-positioning-rail symbols="NQ,MNQ,ES,MES,MGC,SIL"></mkfm-positioning-rail>

Installation

Two files, one script tag. Total payload is 26 KB gzipped — 17 KB library plus a 9 KB offline fallback snapshot, which is optional. No dependencies, no framework, no build step.

1

Add the script once, anywhere in the page

Load it from your own CDN or ours. defer is fine; so is putting it in <head>. The snapshot file is optional but recommended — it is what lets a widget render real numbers when the API is unreachable.

<!-- optional: offline fallback, load first -->
<script src="/vendor/mkfm-snapshot.js"></script>
<script src="/vendor/mkfm-widgets.js" defer></script>

Both files are served from this page's directory, so you can pull them straight down and drop them behind your own CDN: mkfm-widgets.js and mkfm-snapshot.js. Nothing in either file is host-specific — no keys, no origin checks, no phone-home.

2

Drop a widget wherever you want it

They are custom elements. Put them in your template, your React JSX, your Vue template, or inject them with innerHTML — all four work. Each one renders into a shadow root, so your CSS cannot break it and its CSS cannot leak into your dashboard.

<mkfm-positioning-card symbol="MNQ"></mkfm-positioning-card>

<mkfm-positioning-rail symbols="NQ,MNQ,ES,MES,MGC,SIL"></mkfm-positioning-rail>

If your dashboard injects markup at runtime and custom element names are awkward to emit, use the data-mkfm form instead. A MutationObserver upgrades these automatically whenever they appear.

<div data-mkfm="card" data-symbol="MNQ"></div>
3

Point it at your endpoint

Set this before the widget script loads. Everything is optional — the defaults are the values below.

<script>
  window.MKFM_CONFIG = {
    endpoint: 'https://www.marketframework.com/api/aggregator/cohort-intraday?interval=5m',
    link:     'https://www.marketframework.com/tools/positioning-edge',
    refreshMs: 60000,                 // poll interval while the market is open
    symbols:   ['NQ','MNQ','ES','MES','MGC','SIL']
  };
</script>

Events

Every widget emits composed, bubbling events, so you can listen on any ancestor — they cross the shadow boundary and reach document.

document.addEventListener('mkfm:ready', e => {
  // e.detail = { status: 'ok'|'closed'|'stale'|'empty', source: 'live'|'snapshot', version }
  analytics.track('positioning_widget_render', e.detail);
});
document.addEventListener('mkfm:symbolchange', e => console.log(e.detail.symbol));
document.addEventListener('mkfm:error',        e => console.warn(e.detail.error));

Framework notes

  • React — custom elements work in React 19 natively. On React 18 or older, set symbol via a ref (ref.current.setAttribute(...)) rather than as a JSX prop, because React 18 assigns unknown props as properties, not attributes.
  • Vue — add mkfm- to compilerOptions.isCustomElement so Vue stops warning about unresolved components.
  • Next.js / SSR — the element renders nothing on the server and hydrates on the client. No window is not defined. Reserve 150px for the card to avoid layout shift.
  • Content Security Policy — needs script-src for wherever you host the file and connect-src for the API host. No eval, no inline styles injected into your document, no external fonts, no third-party requests of any kind beyond the one API call. The only images are inline data URIs.

If you would rather not run third-party JavaScript

Understandable, and the widgets support it. Host this file yourself and embed it in an iframe — you get the same widget in a hard security boundary, at the cost of having to fix the height yourself.

<iframe src="/vendor/mkfm-embed.html?w=card&symbol=MNQ"
        width="360" height="150" frameborder="0" scrolling="no"
        title="MarketFramework positioning"
        sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"></iframe>

mkfm-embed.html ships in this bundle — it is the same library with a whitelisted query-string router around it (w, symbol, symbols, endpoint). Drop it next to the two JS files. The card is a fixed 360×150 so the iframe needs no height logic; for the rail the page posts {type:'mkfm:height', height: n} to the parent on every repaint — pin the origin on your side before acting on it.

How it fails

This is the part that matters on a live trading dashboard. Use the state switchers above to see each of these for real, on any of the three widgets.

SituationWhat the user seesDetected by
Market closed
weekend, or the 17:00–18:00 ET halt		 Grey CLOSED chip. Last completed session stays on screen, footer relabels to "Last session · date", and the chip's tooltip counts down to the reopen. Polling stops until the reopen so we are not hammering your users' connections overnight. CME Globex hours evaluated in America/New_York via Intl.DateTimeFormat, so DST is correct without hardcoded offsets. Feed's own sessionStatus wins if it disagrees.
Feed unreachable
API down, CORS, DNS, timeout		 The bundled snapshot renders — real numbers from the last packaged session, never zeros or placeholders. Footer relabels to "Cached · date", which dates the data without flagging the widget. No warning chip, no warning band: on a partner dashboard those read as "this product is broken" rather than "this reading is a few minutes old", and the footer already says everything true. 8s AbortController timeout, then the snapshot. The fetch chain always resolves, so a widget can always paint something truthful.
Feed stale
reachable but not updating		 Same as above — values render, the LIVE chip drops away, and the footer carries the date. The distinction between "live" and "a few minutes behind" is visible to anyone who looks at the timestamp and invisible to anyone who does not, which is the right weighting for a headline number on someone else's dashboard. generatedAt older than 15 minutes while the market is open.
No data at all
no API, no snapshot, unknown symbol		 A single line — "Positioning data is unavailable right now" — with the MarketFramework mark still linked. Correct size, no broken layout, no console spew. Null after normalisation.
Widget throws
shouldn't happen; planned for anyway		 Falls back to the same one-line box. The exception is caught at the render boundary, so a bug in our widget can never take down your dashboard. try/catch around every render, plus an mkfm:error event you can log.

One honest gap: exchange holidays are not modelled. On Thanksgiving the clock thinks the market is open, the feed does not update, and the widget renders the last session without the CLOSED note it should show. The values are right and dated; only the label is missing. It is a two-line fix once we agree on a holiday source.

What these numbers are

Everything on the face of these widgets is computed from the live feed. Where the original mockups showed a figure the feed cannot currently produce, the slot was re-filled rather than faked:

Mockup showedShips asWhy
"for 4h 28m""4h 25m", real The cohort feed buckets positioning every 5 minutes, so the minute the stance flipped is a real timestamp. Counted from the flip bucket to the latest one.
"−485.57 since"shown only when price is in the feed Real when present: close before the run began → latest close. The cohort endpoint carries no price, so on that endpoint it is omitted rather than estimated.
"✓ 40/50 candles"number of trades Held pending your call — see below.

No accuracy figure ships in this build — no percentage and no n-of-m count. That slot is deliberately parked until you tell us how you want a hit rate defined: over what horizon, against what price reference, and counted per signal or per bar. Those three choices move the number a long way, and it is the first thing a sharp user will try to reproduce, so it should be your definition rather than ours. The slot currently shows the number of trades behind the reading — factual, supports the "250K trades/day" credibility angle, and makes no forecast claim.

To be explicit about what that does not cover: trade and volume counts are still on the face of all three widgets. They describe sample size, not accuracy, and removing them would leave the reader with no sense of how much activity a reading rests on. Say the word and they come off too.

What we need from your side

These are all on the MarketFramework side. Nothing here is asked of TradeSyncer beyond adding the script tag.

1 · One CORS header — the only thing blocking live data

The widgets point at the same endpoint the live Positioning Edge tool calls: www.marketframework.com/api/aggregator/cohort-intraday?interval=5m. It is public, unauthenticated, and it answers — verified by cross-origin request from an unrelated domain: mode:'no-cors' returns an opaque response (so the server is reached and replies) while mode:'cors' throws. The response carries cache-control and content-type and nothing else. There is no auth wall and no IP restriction. One missing response header is the entire blocker, and in a Next.js app it is a headers() entry:

// next.config.js
async headers() {
  return [{
    source: '/api/aggregator/:path*',
    headers: [
      { key: 'Access-Control-Allow-Origin',  value: 'https://app.tradesyncer.com' },
      { key: 'Access-Control-Allow-Methods', value: 'GET, OPTIONS' },
      { key: 'Access-Control-Max-Age',       value: '600' },
    ],
  }]
}

Until that ships, every widget falls through to the bundled snapshot and renders the last packaged session, dated in the footer. That path is deliberate — the widgets are built to survive it — but nothing on the page is live until the header exists, prices included. If you would rather not open CORS at all, the alternative is a proxy: point MKFM_CONFIG.endpoint at a path on your own origin and cache it 30 seconds server-side. One line of config on our side, and one upstream request per 30s no matter how many dashboards are open.

2 · A card-sized snapshot route — performance, not blocking

The cohort endpoint returns 133 KB — 291 five-minute buckets across all six instruments — and the symbols= filter is not honoured, so a 360×150 card that displays two numbers still pulls the whole thing. A trimmed route (latest bucket only, optionally filtered by symbol) would cut it by roughly two orders of magnitude. Until it exists, the library shares one fetch across every widget on the page, so the cost is paid once per page rather than once per widget.

3 · Quote coverage for the micro contracts — two of six cells are blank

The rail prints last price and session change beside each instrument, read from /api/aggregator/delayed-quotes. That feed returns — for MGC and SIL on every request, so the widget asks for GC and SI instead — the full-size contracts on the same underlying at the same price per ounce. It is a workaround, and it should be a confirmation: either the micros get quotes, or someone tells us the substitution is the right call.

4 · A stable prior-close basis on the quotes feed — correctness

Measured live, seconds apart: GC returned a session change of −37,485.71% and ES returned −99.10% against a price that had moved half a point. Both self-corrected on the next read, so the break is in the prior-close basis rather than the price. The widget recomputes the change from price and priorPrice and suppresses anything past ±25%, which means a bad tick shows no number instead of an alarming wrong one. Fixing it upstream would let us drop the guard.
